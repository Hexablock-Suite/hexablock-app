Interface adapters (presenters, view models, mappers, repository implementations). It may import `src/application/` and `src/domain/`.

Today it holds `InMemoryGameRepository`, the adapter of the `GameRepository` port, and `NullGameEventPublisher`, a `GameEventPublisher` that does nothing. Each adapter runs the contract suite of its port in `test/support/contracts/`, the same suite as the test fake.

`GameEventBus` is the event bus of the app (#362, Observer of view 4.3). It implements the `GameEventPublisher` port, and the composition root gives one bus to every `ApplyMove`. A `GameEventListener` subscribes to it with `subscribe(listener)`, which returns the operation that removes the listener. `publish(event)` gives the event to each listener in the order of subscription, and the bus names no event class. A listener that throws does not stop the others: the bus gives the event to every listener and then throws one `Error` with the failures as its `cause`, so `ApplyMove` counts one failed delivery. `AchievementCounterListener` is the first listener. Since #363 it saves the counters of the achievements of each game through the `AchievementCounterRepository` port: the lines of a `LinesCleared` and the tile of a `TileMerged` are a best count, and each `StackCleared`, one goal of Hexa Sort, adds one to the total. The bus waits for nothing, so the listener queues each save after the save before it, and `saved()` waits for the queue and throws one `Error` with the failed saves as its `cause`. A failed save writes nothing, and the next saves still run. A listener tells one event from another with `instanceof` and reads its data through `deliverTo()`. No listener of this layer imports a driver of `src/infrastructure/` (rule R-adapters-imports).

`HomePresenter` is the MVP presenter of the home screen and of the game selector map (#169). Since #188 its home view model also holds the label of the button that opens the achievements screen. It takes the ids of the registered games, the board figures of the root, the texts of one language and, since #181, the saved progress of each game, and it imports no React. It finds the texts of each game under `game.<id>.name` and `game.<id>.place` in the catalog, and the choice of a game whose saved progress keeps a high score also carries the record text of the new `map.highScore` key, composed with the `Score` that the presenter reads through `deliverTo()` (rule R-no-delivery-call).

`GamePresenter` is the MVP presenter of the game screen (#170). It calls `StartGame` and `ApplyMove` through the `UseCase` port, passes the optional `LevelId` of `onStart(levelId?)` to `StartGame` (#172), reads only the plain `MoveResult`, and builds `GameViewModel` with the `StateMapper` of the game: one pair of a coordinate and a cell view for each space of the board, free or occupied. It imports no React and names no variant. `SpaceStateMapper` is the default mapper, which the game registry gives every game until its variant registers its own. `FitStateMapper` is the mapper of Hexa Fit (#175): the piece of each space, the tray at each rotation step and the move count. `MergeStateMapper` is the mapper of Hexa Merge (#177): the number of each tile and the target flag of the payload. The texts of the game screen live under `play.<part>` in the catalog. Its table of failure texts is a `Record<FailureCode, TextKey>` with one entry for each failure code (#322, decision 62 of the class diagram): `move-rejected`, `nothing-to-undo` and `nothing-to-redo` have their own texts, and every other code names the general text `play.error`. So a new code with no text fails `pnpm typecheck`.

`AchievementsPresenter` is the MVP presenter of the achievements screen (#188). It calls `ListAchievements` through the `UseCase` port and puts each achievement in one of two sections, in progress or completed, in the order of the list. It imports no React. The texts of the screen live under `achievements.<part>` in the catalog, and the name of each achievement under `achievement.<id>`.

`key-value-store.ts` holds `KeyValueStore`, the driver interface of the local storage (issue #155). It keeps one text value for each text key. The local repositories of this layer use it, and `DeviceKeyValueStore` in `src/infrastructure/` implements it, so no adapter imports a storage package. `InMemoryKeyValueStore` in `test/support/adapters/` is its test fake, for the integration tests of APP-NFR-15.

`LocalProgressRepository` is the adapter of the `ProgressRepository` port over `KeyValueStore` (#164, decision 57 of the class diagram). It keeps the `GameProgress` of each game as one JSON text of plain numbers and texts under the key `progress:<game id>`, with a `version` field. It reads each value of the domain with `deliverTo(receiver)` (rule R-no-delivery-call), and it builds a loaded progress again with `GameProgress.start()`, `recordScore()` and `recordLevel()`. A saved progress that it cannot read throws, and it never writes over it. It runs the contract suite of its port in `test/support/contracts/`.

`LocalAchievementCounterRepository` is the adapter of the `AchievementCounterRepository` port over the same `KeyValueStore` (#363, decision 57 of the class diagram). It keeps the `AchievementCounters` of each game as one JSON text under its own key `achievement-counters:<game id>`, with a `version` field, so the saved progress keeps its shape. It follows `LocalProgressRepository`, and both share the JSON helpers of `saved-json.ts`: a saved text that it cannot read throws, and it never writes over it. It runs the contract suite of its port in `test/support/contracts/`.

It also holds the bundled level files in `levels/<game>/` (issues #166 and #167, A6): one JSON file per hand-made level, in the shared level format of hexablock-api `docs/level-format.md`. `levels/fit/` holds the 15 Fit levels `fit-01` to `fit-15` (APP-FR-05, #49), and `fit-01.json` is the complete Fit example of that document. `levels/sort/` holds the 10 Sort levels `sort-01` to `sort-10`, and `sort-01.json` is the complete Sort example of that document. Each Sort level picks its piece source (A4): `sort-01` draws from a seed, and `sort-02` to `sort-10` give a fixed list of stacks. These 25 levels are hex levels. Since #354 the same folders also hold 3 Fit levels and 3 Sort levels on the square, `fit-square-01` to `fit-square-03` and `sort-square-01` to `sort-square-03`, and 3 of each on the triangle, `fit-triangle-01` to `fit-triangle-03` and `sort-triangle-01` to `sort-triangle-03`. Each figure numbers its levels from 1, and the id names the figure, so a new level of one figure changes no id of another figure. The Sort levels of the square and of the triangle give a fixed list of stacks. `BundledLevelRepository` implements the `LevelRepository` port over them (#168, decision 58 of the class diagram): it imports each file as a JSON module, so the device needs no file system, and it gives the levels whose `gameId` names the asked game. A new level file adds one import to it, and its test reads the folders, so a file that it misses fails the test. A level file is plain data, and an adapter turns it into a `LevelDefinition` of the engine (classes.md decision 24). `levelOf()` finds one level of a game by its id, and the adapter runs the contract suite of its port.

`LevelGameFactories` implements the `GameFactories` port (#172, decision 59 of the class diagram). It gives `StartGame` the `GameFactory` of the registered variant factory of a game, or of a level that it finds in the `LevelRepository` port. The `LevelVariant` of the game turns the `LevelDefinition` into a variant factory: it creates the level builder of the variant, gives it to `buildWith()` and creates the variant factory of the built level. `fitLevelVariant()` and `sortLevelVariant()` live in the same file, the code of layer 3 that knows the variants with levels.

It also holds the typed text catalog in `texts/` (APP-FR-11, issue #154). `es.ts` and `en.ts` hold one Spanish and one English entry for each key, and `text-catalog.ts` joins them. A screen shows a text through its key, never through a literal text (rule R-text-catalog in `AGENTS.md`).
