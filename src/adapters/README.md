Interface adapters (presenters, view models, mappers, repository implementations). It may import `src/application/` and `src/domain/`, and no package and no Node module («The rule of layers 3 and 4» in `docs/architecture/layers.md`).

It holds `InMemoryGameRepository`, the adapter of the `GameRepository` port, and `GameEventBus`, the `GameEventPublisher` that the composition root uses. A root with no store subscribes no listener to the bus, so the bus is also the publisher with no listener (#412). Each adapter runs the contract suite of its port in `test/support/contracts/`, the same suite as the test fake.

`GameEventBus` is the event bus of the app (#362, Observer of view 4.3). It implements the `GameEventPublisher` port, and the composition root gives one bus to every `ApplyMove`. A `GameEventListener` subscribes to it with `subscribe(listener)`, which returns the operation that removes the listener. `publish(event)` gives the event to each listener in the order of subscription, and the bus names no event class. A listener that throws does not stop the others: the bus gives the event to every listener and then throws one `Error` with the failures as its `cause`, so `ApplyMove` counts one failed delivery. `AchievementCounterListener` is the first listener. Since #363 it saves the counters of the achievements of each game through the `AchievementCounterRepository` port. Since #406 each event that counts implements `CountsForAchievements` of the domain and records its own count: the lines of a `LinesCleared` and the tile of a `TileMerged` are a best count, and each `StackCleared`, one goal of Hexa Sort, adds one to the total. The listener names no event class and imports no variant (rule `achievement-listener-no-variants`). The bus waits for nothing, so the listener queues each save after the save before it, and `saved()` waits for the queue. A failed save writes nothing, and the next saves still run. Since #384 the listener takes the `Logger` port of `src/application/logger.ts`, and the composition root gives it the logger of its drivers. Each failed save writes one `failure` entry at once, named `AchievementCounterListener`, with a `save-failed` `UseCaseError` that keeps the thrown value as its `cause`. The listener keeps no failure, and `saved()` never throws. A logger that throws stops no save. A listener may tell one event from another with `instanceof`, and it reads the data of an event through `deliverTo()`. No listener of this layer imports a driver of `src/infrastructure/` (rule R-adapters-imports).

`HomePresenter` is the MVP presenter of the home screen and of the game selector map (#169). Since #188 its home view model also holds the label of the button that opens the achievements screen. It takes the ids of the registered games, the board figures of the root, the texts of one language and, since #181, the saved progress of each game, and it imports no React. It finds the texts of each game under `game.<id>.name` and `game.<id>.place` in the catalog, and the choice of a game whose saved progress keeps a high score also carries the record text of the new `map.highScore` key, composed with the `Score` that the presenter reads through `deliverTo()` (rule R-no-delivery-call).

`GamePresenter` is the MVP presenter of the game screen (#170). It calls `StartGame`, `ApplyMove`, `UndoMove` and `RedoMove` through the `UseCase` port (#178), passes the optional `LevelId` of `onStart(levelId?)` to `StartGame` (#172), turns the intent of `onMove(intent)` into the domain move with the `MoveMapper` of the game before `ApplyMove` (#405), reads only the plain `MoveResult`, and builds `GameViewModel` with the `StateMapper` of the game: one pair of a coordinate and a cell view for each space of the board, free or occupied. It imports no React and names no variant. Each variant has its own mapper, and the game registry gives no default mapper. `space-view.ts` holds `SpaceView`, the view of a free or an occupied space, which `SpaceCellRenderer` draws. `FitStateMapper` is the mapper of Hexa Fit (#175): the piece of each space, the tray at each rotation step and the move count. `MergeStateMapper` is the mapper of Hexa Merge (#177): the number of each tile and the target flag of the payload. `move-mapper.ts` holds `MoveMapper<TIntent, TMove>` (#405, decision 14): the move controls of layer 4 send a plain intent, and `toMove(intent)` turns it into the move of the domain, so no control imports a class of a variant. `LinesMoveMapper` turns a tray index into a `TrayPosition` and builds the `PlacePiece`, `FitMoveMapper` turns a text id into a `PieceId` and a rotation step into `Turns` and builds the `PlaceFitPiece` or the `RemoveFitPiece`, `SortMoveMapper` builds the `PlaceStack` on the pressed space, and `MergeMoveMapper` gives the `Slide` of the compass name of a way. The Lines and the Fit mappers take the optional step of the board figure from a pressed space to the offset of the move (#174, #365). `merge-slide-ways.ts` holds `slideWays()`, which gives the slides of a Merge board with the way of each one on the screen of the figure, and `nearestWay()`, which picks the way nearest to an angle (#177, #292). It names the `Slide` of Hexa Merge, so it lives next to the Merge mappers, not in `board/` (#409). The controls read only the compass name and the angle of a way, a `ScreenWay`. The texts of the game screen live under `play.<part>` in the catalog. Its table of failure texts is a `Record<FailureCode, TextKey>` with one entry for each failure code (#322, decision 62 of the class diagram): `move-rejected`, `nothing-to-undo`, `nothing-to-redo` and `level-locked` (#397) have their own texts, and every other code names the general text `play.error`. So a new code with no text fails `pnpm typecheck`.

`ResultPresenter` is the MVP presenter of the victory screen and of the defeat screen (#180, APP-FR-07). `GamePresenter` gives it the response of the move that ends a game through `GameEndListener`. It builds the `GameResult` from the value objects of that response: a level result for a won level, and an endless result with the score only for a game with no levels (D26). A lost level saves nothing. It saves the result through the `SaveProgress` of the level that the root gives (`saveProgressOf(levelId)`), and after a won level it asks `ListLevels` for the next level, which it offers when that level is not locked. Its table of failure texts is a `Record<FailureCode, TextKey>`: `save-failed` has its own text, and every other code names `result.error`. `LevelGameFactories.progressModelFor(levelId)` gives the progress model of a level, and the factory of a level gives its level id to each game (decision 61 of the class diagram). The texts of the result screens live under `result.<part>` in the catalog.

`AchievementsPresenter` is the MVP presenter of the achievements screen (#188). It calls `ListAchievements` through the `UseCase` port and puts each achievement in one of two sections, in progress or completed, in the order of the list. It imports no React. The texts of the screen live under `achievements.<part>` in the catalog, and the name of each achievement under `achievement.<id>`.

`LevelSelectorPresenter` is the MVP presenter of the level selector (#173). It calls `ListLevels` through the `UseCase` port with the game and the figure of its screen, and gives one `LevelChoice` per level, in the order of the list: the text of the level id, the name from its place in the list, the text of its status, whether it is completed and whether a press starts it, and the stars of a completed level. It reads the `LevelStatus` that `ListLevels` gives with `equals()` and holds no copy of the rule. A completed level and an open level start, and a locked level does not. An empty list gives the text of no levels, and a failure one error text. Since #307 it also gives `unavailable`, a section after the levels with one `LevelChoice` per unavailable level of the game: the choice names the level by its id, shows the text `levels.status.unavailable` and does not start. The section exists only when the game has an unavailable level, and the app shows no code of the broken rule. It imports no React. The texts of the screen live under `levels.<part>` and `levels.status.<status>` in the catalog.

`delivered.ts` holds the one way of this layer to read a value of the domain (#408, rule R-no-delivery-call). `valueOf(source)` gives the value that a value object delivers through `deliverTo(receiver)`. `onlyValue(deliver)` gives the one value of a domain object that delivers several parts at once, such as the view of a state or a saved progress. `optionalValueOf()` gives `undefined` for a missing value object. The state mappers, the presenters and the local repositories read each value with them, so no adapter keeps its own copy. A source that delivers no value, or more than one value, throws one `Error`, for example «The domain object delivered 0 values, not 1.». The screen layouts of `board/` keep `valuesOf()`, which gives the two values of a coordinate.

`key-value-store.ts` holds `KeyValueStore`, the driver interface of the local storage (issue #155). It keeps one text value for each text key. The local repositories of this layer use it, and `DeviceKeyValueStore` in `src/infrastructure/` implements it, so no adapter imports a storage package. `InMemoryKeyValueStore` in `test/support/adapters/` is its test fake, for the integration tests of APP-NFR-15.

`api/` holds the layer 3 side of the HTTP client (Q7, option A3, classes.md decision 22, #404). `dto.d.ts` holds the DTO schemas of the backend OpenAPI document. `pnpm api:generate` writes it, together with `src/infrastructure/api/schema.d.ts`, which holds the paths and imports these DTO types, and `pnpm api:check` compares both files. Do not edit it by hand (rule R-api-contract). `health-api.ts` holds `HealthApi`, the transport interface of the health resource: one interface per resource of the backend, whose methods take and give DTO types and never a type of the HTTP library. It is not a port, because layer 2 never sees it. `ApiClient` of `src/infrastructure/api/client.ts` implements it, so no adapter imports `openapi-fetch`. The HTTP repositories `ApiProgressRepository`, `ApiLevelRepository`, `ApiLeaderboardGateway` and `ApiAccountGateway` and their mapper `ApiDtoMapper` live in this folder too: #45, #46 and #47 build the planned ones over the transport interfaces. `levels-api.ts` holds `LevelsApi`, the transport interface of the levels resource, whose `getLevels()` gives the answer of `GET /v1/levels` (#48). `ApiLevelRepository` implements the `LevelRepository` port over it. A level of the answer is in the shared level format of a level file, so the adapter reads it with `LevelDefinition.of()`, as `BundledLevelRepository` reads a file, and `ApiDtoMapper` maps no level. `unavailable()` gives the id of each level of the game that the answer names in `unavailable`, a stored level that breaks a rule (#307). A failed request rejects each call, and the adapter keeps no copy of an answer. It runs the contract suite of its port.

`LocalProgressRepository` is the adapter of the `ProgressRepository` port over `KeyValueStore` (#164, decision 57 of the class diagram). It keeps the `GameProgress` of each game as one JSON text of plain numbers and texts under the key `progress:<game id>`, with a `version` field. It reads each value of the domain with `deliverTo(receiver)` (rule R-no-delivery-call), and it builds a loaded progress again with `GameProgress.start()`, `recordScore()` and `recordLevel()`. A saved progress that it cannot read throws, and it never writes over it. It runs the contract suite of its port in `test/support/contracts/`.

`LocalAchievementCounterRepository` is the adapter of the `AchievementCounterRepository` port over the same `KeyValueStore` (#363, decision 57 of the class diagram). It keeps the `AchievementCounters` of each game as one JSON text under its own key `achievement-counters:<game id>`, with a `version` field, so the saved progress keeps its shape. It follows `LocalProgressRepository`, and both share the JSON helpers of `saved-json.ts` and the delivery helpers of `delivered.ts`: a saved text that it cannot read throws, and it never writes over it. It runs the contract suite of its port in `test/support/contracts/`.

It also holds the bundled level files in `levels/<game>/` (issues #166 and #167, A6): one JSON file per hand-made level, in the shared level format of hexablock-api `docs/level-format.md`. `levels/fit/` holds the 15 Fit levels `fit-01` to `fit-15` (APP-FR-05, #49), and `fit-01.json` is the complete Fit example of that document. `levels/sort/` holds the 10 Sort levels `sort-01` to `sort-10`, and `sort-01.json` is the complete Sort example of that document. Each Sort level picks its piece source (A4): `sort-01` draws from a seed, and `sort-02` to `sort-10` give a fixed list of stacks. These 25 levels are hex levels. Since #354 the same folders also hold 3 Fit levels and 3 Sort levels on the square, `fit-square-01` to `fit-square-03` and `sort-square-01` to `sort-square-03`, and 3 of each on the triangle, `fit-triangle-01` to `fit-triangle-03` and `sort-triangle-01` to `sort-triangle-03`. Each figure numbers its levels from 1, and the id names the figure, so a new level of one figure changes no id of another figure. The Sort levels of the square and of the triangle give a fixed list of stacks. `BundledLevelRepository` implements the `LevelRepository` port over them (#168, decision 58 of the class diagram): it imports each file as a JSON module, so the device needs no file system, and it gives the levels whose `gameId` names the asked game. A new level file adds one import to it, and its test reads the folders, so a file that it misses fails the test. A level file is plain data, and an adapter turns it into a `LevelDefinition` of the engine (classes.md decision 24). `levelOf()` finds one level of a game by its id, and the adapter runs the contract suite of its port. Since #48 `BundledLevelRepository` reads the `version` of each file, and it names no unavailable level. `CombinedLevelRepository` implements the same port over two repositories of it, a Composite: the composition root gives it the bundled levels and `ApiLevelRepository`. The bundled levels always come, and a backend that does not answer counts as a backend with no level, so every bundled level opens with the network off. A backend level whose id no bundled level has adds a level. When both hold a copy of one level, `LevelDefinition.replaces()` decides (DS-11): the backend copy wins only with a higher version. An unavailable backend level with a bundled copy is not unavailable: the bundled copy plays (#307).

`LevelGameFactories` implements the `GameFactories` port (#172, decision 59 of the class diagram). It gives `StartGame` the `GameFactory` of the registered variant factory of a game, or of a level that it finds in the `LevelRepository` port. The `LevelVariant` of the game turns the `LevelDefinition` into a variant factory: it creates the level builder of the variant, gives it to `buildWith()` and creates the variant factory of the built level. `LevelVariant` lives in `src/domain/engine/`, and each variant folder holds its level function, `fitLevelVariant()` and `sortLevelVariant()` (#407). So the adapter names no variant (rule `level-game-factories-no-variants`).

`board/` holds the screen layout of each board figure (#393, decision 17 of the class diagram). `BoardLayout` is the screen layout of a figure, and `HexLayout`, `SquareLayout` and `TriangleLayout` implement it: each one turns a domain coordinate into the center and the corners of its cell on the screen, in density-independent pixels. `cellBoxOf()` gives the box of a cell from its outline. `fittedCellSize()` gives the widest cell at which a board fits the width of the screen. They are pure conversions and import no package and no variant (rule `board-layouts-no-variants`, #409). The board components of `src/infrastructure/board/` read them.

It also holds the typed text catalog in `texts/` (APP-FR-11, issue #154). `es.ts` and `en.ts` hold one Spanish and one English entry for each key, and `text-catalog.ts` joins them. A screen shows a text through its key, never through a literal text (rule R-text-catalog in `AGENTS.md`).
