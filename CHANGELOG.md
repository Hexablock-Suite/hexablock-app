# Changelog

All notable changes to this repository are documented in this file. The format follows [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning 2.0.0](https://semver.org/spec/v2.0.0.html).

Each sprint of [`docs/ROADMAP.md`](docs/ROADMAP.md) closes with a version section and a `v0.N.0` tag (rule R-sprint-release in `AGENTS.md`). The final delivery is `v1.0.0`.

## [Unreleased]

### Added

- The time of a Hexa Fit level ([#157](https://github.com/Hexablock-Suite/hexablock-app/issues/157), APP-FR-09, classes.md decisions 19, 27 and 29). `TimedRulesDecorator` in `src/domain/engine/timed-rules-decorator.ts` implements `IGameRules`, wraps any rules and times the game with a `LevelTimer` that reads the time through `Clock`. It wraps `playTurn()`, because `GameEngine` calls only that method: the timer starts on the first accepted turn, stops when that turn ends the game, and a rejected move leaves it alone. `FitFactory` takes a `Clock` as its third constructor parameter and wraps `FitRules` in the decorator with a new timer for each game, so `FitRules` holds no timer code. `IGameRules` gains `timed(): ITimed | undefined` (`BaseGameRules` returns `undefined`), `GameEngine.timed()` reads it (decision 27), and `MoveResult.elapsedMs` carries the time of a timed game, so a later presenter can build a `GameResult` with it. The timer lives outside the cloned state: an undo takes a move back and the clock goes on.
- The undo history and the `UndoMove` use case ([#159](https://github.com/Hexablock-Suite/hexablock-app/issues/159), APP-FR-08, classes.md decisions 3, 27 and 34). `MoveCommand` keeps the state before a move, and `MoveHistory` keeps the commands with an optional limit and implements `IUndoable` (`src/domain/engine/undo-capabilities.ts`). `IVariantFactory` gains `createHistory()`: Fit gets a `MoveHistory` with no limit, Merge one with limit 1, and Lines and Sort none. `GameEngine` takes the history as its last optional parameter, gives each saved turn a clone of the state before the move, and takes that clone back through its private `restore()`, which `MoveCommand.undo()` calls. A paused game refuses the undo, and a finished or restarted game forgets its moves. `UndoMove` names no variant and returns `no-running-game`, `no-undo`, `nothing-to-undo` or `undo-failed`. `MoveResult.hasUndo`, `canUndo` and `canRedo` read the capabilities of the engine. The undo gives back the cloned piece source, so the random state comes back too (S3-15 in [#151](https://github.com/Hexablock-Suite/hexablock-app/issues/151), «Propuesta, pendiente del equipo»). Redo waits for `RedoableHistory`: `GameEngine.redoable()` exists, and no history implements `IRedoable` yet.
- The plain variant data in `MoveResult` ([#158](https://github.com/Hexablock-Suite/hexablock-app/issues/158), classes.md decisions 14 and 29). `BoardState` gains `view()`, which returns plain immutable data that each variant state builds from values it holds: `LinesState` the tray, `SortState` the offered stack and the goal counts, `FitState` the remaining and placed pieces, and `MergeState` the target flag. `MoveResult` carries it as `payload`, typed by the state through `ViewOf<TState>`. `moveResultOf()` only copies it, so `StartGame` and `ApplyMove` stay blind to the variant and `IVariantFactory` does not change. `MoveResult.hasUndo` says whether the variant has undo at all, and it is `false` for every variant until the undo history comes (#159). The new dependency-cruiser rule `application-no-variants` forbids `src/application/` to import `src/domain/variants/`. Decisions 14 and 29 and their class views show the payload, and the PNG images of the changed views are exported again.
- The real square and triangle geometries and one topology contract suite ([#160](https://github.com/Hexablock-Suite/hexablock-app/issues/160), APP-FR-16, classes.md decision 17). `SquareGeometry` with `SquareTopology` and `TriangleGeometry` with `TriangleTopology` implement `GeometryFactory<TCoord>`, and the doubles in `test/support/engine/` now only re-export them. `square()` and `triangle()` reject a value that is not a safe integer and freeze the coordinate. `GridTopology` gains `neighbor(c, direction)`, so each of the three real topologies rejects, with a `RangeError`, an axis or a direction that it lacks, also a cast name such as `constructor`. Each family holds seven piece shapes of 1 to 5 cells as one data list. `test/domain/engine/topology-contract.test.ts` runs the same `GridTopology` tests on the three topologies, with the region cell count of each one.
- The geometry family and the board builder in the engine ([#153](https://github.com/Hexablock-Suite/hexablock-app/issues/153), APP-FR-16, classes.md decisions 15 and 17). `GeometryFactory<TCoord>` creates the coordinate, the topology and the piece shapes of one geometry. `HexGeometry` is the real family, with `HexCoord`, `hex()` and `HexTopology` promoted from the Merge test double. `hex()` now rejects a value that is not a safe integer and freezes the coordinate, and `line()` also rejects a cast axis such as `constructor`. `BoardBuilder<TCoord>` builds a `Board` with `withRegion()` or `withFigure()`. Each step returns the builder, and only `build()` returns the board, through the `Board` constructor, so the checks of the board apply. The Merge tests and the one-board gate now run on the real geometry. The comment on `GridTopology` no longer asks for a direction check, because no method takes a direction.

### Changed

- `LevelTimer` is an entity of the `GameEngine` aggregate with an id of its own ([#214](https://github.com/Hexablock-Suite/hexablock-app/issues/214), classes.md decisions 19, 25, 26, 40 and 50). `LevelTimerId` in `src/domain/engine/level-timer-id.ts` is a value object in the form of `BoardId`: `LevelTimerId.of(value)` throws a `RangeError` for an empty or blank text, the value is private, and `equals()` compares two ids. `LevelTimerIdGenerator` in `src/domain/engine/level-timer-id-generator.ts` is an engine interface in the form of `BoardIdGenerator`, which layer 4 implements. **Signature changes.** `new LevelTimer(clock)` becomes `new LevelTimer(id, clock)`, and `new FitFactory(geometry, level, clock)` becomes `new FitFactory(geometry, level, clock, timerIds)`: the composition root (#162) must give `FitFactory` a `LevelTimerIdGenerator`. `LevelTimer.equals(other)` is new and compares two timers by their id only, whatever their clock readings hold. `FitFactory.createRules()` asks the generator for one id in each call. `IVariantFactory.createRules()`, `GameFactory`, `ITimed` and the three variants with no timer do not change, and the root keeps no field for the timer: it reaches it through `IGameRules.timed()`.
