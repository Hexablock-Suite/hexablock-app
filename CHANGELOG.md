# Changelog

All notable changes to this repository are documented in this file. The format follows [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning 2.0.0](https://semver.org/spec/v2.0.0.html).

Each sprint of [`docs/ROADMAP.md`](docs/ROADMAP.md) closes with a version section and a `v0.N.0` tag (rule R-sprint-release in `AGENTS.md`). The final delivery is `v1.0.0`.

## [Unreleased]

### Added

- The new tiles of Hexa Merge ([#95](https://github.com/Hexablock-Suite/hexablock-app/issues/95), APP-NFR-07): after each accepted slide, `MergeRules.resolve()` puts one new tile on an empty cell. `mergeTileSource(seed, fourChance)` in `src/domain/variants/hexa-merge/merge-tile-source.ts` reuses the engine `SeededPieceSource`, and each draw (`NewTile`) gives both the cell and the value, so the same seed always gives the same new tiles. `MergeState` holds the source as `tiles`, and `clone()` clones it, so a cloned state gives the same new tile again. The values code against the proposal on [#57](https://github.com/Hexablock-Suite/hexablock-app/issues/57), «Propuesta, pendiente del equipo»: a 2 with 0.9 and a 4 with 0.1, and undo restores the cloned state. A `fourChance` outside [0, 1] throws a `RangeError`. The game now ends when an accepted slide and its new tile leave no slide that changes the board. The suite `test/domain/variants/hexa-merge/merge-tiles.test.ts` plays through `GameEngine.play()` and lints the Merge code with the domain purity rule.
- Hexa Merge in `src/domain/variants/hexa-merge/` ([#94](https://github.com/Hexablock-Suite/hexablock-app/issues/94)): the bound `IMergeable<T>`, the value object `MergeTile` (a power of two of 2 or more, A1), the move `Slide` (an axis of the topology and a sense, so a hexagon has six slides), `MergeState` and `MergeRules<TCell extends IMergeable<TCell>, TCoord, TAxis>`, which extends `BaseGameRules`. A slide moves every tile to the edge and merges two equal tiles into one of double value. The rules code against the proposal on [#57](https://github.com/Hexablock-Suite/hexablock-app/issues/57), «Propuesta, pendiente del equipo»: each line is read from its leading edge, and a tile merges at most once per move (`2 2 2` gives `4 2`). A slide that changes no cell is rejected, and the game ends when no slide changes the board. The target tile sets `targetReached` and the game goes on (A3). `MergeState.merged` keeps the tiles of the last move for the scoring of #97. The rules suite `test/domain/variants/hexa-merge/merge-rules.test.ts` runs on a hexagonal topology double in `test/support/variants/hexa-merge/`. The README moves the `IMergeable` row from design to code, in a «Variant bounds» table, because the bounds gate reads only the engine.
- Hexa Lines in `src/domain/variants/hexa-lines/`: `LinesState` over the generic `Board` with `Color` cells, the tray of 3 pieces and the piece source; `PlacePiece` as the move; and `LinesRules`, which extends `BaseGameRules`. It places a tray piece, clears the full lines on every axis that the topology gives, and ends the game when no tray piece fits. `validMoves()` is a lazy generator. No cell falls after a clear (no gravity). The combo and the streak follow the proposal on [#58](https://github.com/Hexablock-Suite/hexablock-app/issues/58), «Propuesta, pendiente del equipo»; `LinesState` keeps `streak` and `linesCleared` for the scoring of #97. The rules suite runs on the square and triangle test doubles ([#91](https://github.com/Hexablock-Suite/hexablock-app/issues/91)).
- Tests that close the review gaps of the merged `GameEngine` ([#71](https://github.com/Hexablock-Suite/hexablock-app/issues/71)): a reentrant `play()` from `score()` throws a `RangeError`, because the engine is in the resolving phase; `start()` after a game over starts a new game; and rules that throw in `apply()` or in `evaluate()` leave the board, the score and the phase unchanged.
- Tests that close the review gaps of the merged shapes, pieces and rules ([#69](https://github.com/Hexablock-Suite/hexablock-app/issues/69), [#70](https://github.com/Hexablock-Suite/hexablock-app/issues/70)): a group of groups lists, counts, translates and rotates every level; a negative offset keeps the orientation of each triangle; a piece that turns back one step and forward one step returns to the start; `playTurn()` returns the rejected resolution when `resolve()` refuses the move after `apply()`, and the engine keeps its old board then; a type-level check fails `pnpm typecheck` when `Outcome` gets a value that a `switch` does not handle; and the name of each of the five phases.
- Tests that close the review gaps of the merged board ([#67](https://github.com/Hexablock-Suite/hexablock-app/issues/67)): `clone()` shares the cell objects, because a cell is a value, and `board.ts`, `README.md` and `docs/architecture/classes.md` now say so.

### Changed

- `GameEngine.play()` closes the second review of the Sprint 1 engine. A rejected move always returns `playing`, even when its resolution carries a final outcome, and `Resolution.evaluated()` throws on a rejected resolution. The scoring policy works on a copy of the state, and a score that is not finite throws a `RangeError` before the commit. The engine computes the next phase before the commit, so an unknown outcome throws a `RangeError` and leaves the board, the score and the phase unchanged. `pause()` before `start()` throws, as `play()` does. Tests pin that a failing publisher leaves the turn committed, that the rollback does not cover the piece source the rules hold, and that a victory publishes `GameOver` with `victory`.
- The board and the value objects reject input that the second review found. `Board.line()` from a coordinate off the board yields nothing. The `Board` constructor throws a `RangeError` for initial content off the shape or with a key that does not match its coordinate, and it copies each entry. `ProgressRecord.of()` throws for a score or stars that are not finite. `Radius`, `RegionSize` and `Turns` take safe integers only and store `-0` as `0`. `ShapeGroup` freezes its copy of the children. Tests pin the one-shot iterables of the board and `validMoves()`, and a seeded source that continues its sequence across two loops.
- A piece source lives in the variant state, so the rollback of `GameEngine.play()` covers it: a turn retried after a throw draws the same piece, and a move rejected after `apply()` keeps the source position. `IPieceSource` and `RandomSource` are `Cloneable`, and `SeededPieceSource`, `FixedListPieceSource` and `Mulberry32Random` copy their position or generator state in `clone()` (`docs/architecture/classes.md` decision 31). The swap test of [#74](https://github.com/Hexablock-Suite/hexablock-app/issues/74) runs two dummies of each interface through the engine, and the progress model records the `GameResult` that a subscriber builds from `GameOver`.
- The primitive-types gate also reads exported variables (`export const`, `export let`, destructured names included), so an exported `number` or `string` constant needs a README row.
- Every class view of the engine and of the extensibility guide draws only what the code has, or marks planned design with a `«Sprint N»` stereotype that each legend explains. Views 1 and 7 draw `Resolution`, and view 1 draws `Outcome` as a literal union. The `BoardShape` to `ShapeNode` arrow is removed, because no document plans it. `ext-1` to `ext-3` give `createBoard()` and `build()` the three-parameter `Board`, and `withRegion()` takes a `RegionSize`.
- The engine docs match the Sprint 1 code after the second review. In `docs/architecture/classes.md`, decisions 16, 21, 31 and 33 give the real type parameters, the two guards on a rejected move and the rollback scope. `docs/REQUIREMENTS.md` D10 and `docs/architecture/layers.md` give the three-parameter `Board` and `GridTopology`. The README Design Patterns rows link their code, and the `GameId.of` and `Board` rows state the new checks. `docs/ROADMAP.md` Sprint 1 lists APP-NFR-25. Seven class views (`engine-1`, `engine-2`, `engine-4` to `engine-7` and `overview-engine`) are redrawn to show the members the code has.
- `GameId.of()` throws a `RangeError` when the id is not a lowercase kebab-case slug, for example `Hexa Fit` or `hexa\tfit` ([#70](https://github.com/Hexablock-Suite/hexablock-app/issues/70)). It no longer trims the value: an id with a space or a tab around it is an error too.
- `BaseGameRules.playTurn()` no longer calls `evaluate()` when `resolve()` rejects the move, so a rejected move keeps the outcome `playing` ([#70](https://github.com/Hexablock-Suite/hexablock-app/issues/70)).
- `BoardShape.of([])` throws a `RangeError`, and `new Board(shape, topology)` throws a `RangeError` when two coordinates of the shape have the same topology key: a repeated coordinate or a topology whose keys collide ([#67](https://github.com/Hexablock-Suite/hexablock-app/issues/67)). Before, the board accepted both: two coordinates then shared one stored cell, and the shape counted more cells than the board could hold.
- `GridTopology<TCoord, TAxis, TDirection>` and `Board<TCell, TCoord, TAxis>` carry closed axis and direction unions, so `line()` with an axis that the topology lacks does not compile. `ring()` takes a `Radius`, `region()` a `RegionSize`, `rotate()` and `rotated()` a `Turns`, and `key()` returns a `CoordKey`. The square and triangle doubles declare their own unions. `GameEngine`, `IGameRules` and `BoardState` keep their type parameters. View 2, `classes.md` and the README tables show the new signatures Comments state that the topology owns the format of `CoordKey`, and that a real topology must check an axis at runtime, because a cast such as `'nort' as SquareAxis` compiles. View 2 PNG is rendered again from its HTML ([#86](https://github.com/Hexablock-Suite/hexablock-app/issues/86)).
- The README section «Generic Engine» describes the Sprint 1 code: links to the source files, the members of `GridTopology`, the test doubles, and a bounds table with a Status column that marks `IMergeable<TCell>` on `MergeRules` as a design bound for Sprint 2 ([#75](https://github.com/Hexablock-Suite/hexablock-app/issues/75)).
- Sprint 0 closes with `v0.0.0`: `docs/ROADMAP.md` is approved, the README names the five use case flows and marks the engine sections as design, `AI_USAGE.md` logs the work of 2026-11-03 and 2026-11-04, and APP-FR-16 no longer says the square geometry exists in the engine tests.

Flow 5 and its sequence diagram cite view 3.3 of the API class diagram, not view 4.3 ([#63](https://github.com/Hexablock-Suite/hexablock-app/pull/63)).

- The use case and adapter maps label the uses between groups with a verb, not with a role and a multiplicity ([#63](https://github.com/Hexablock-Suite/hexablock-app/pull/63)).
- The class diagrams draw use arrows between layers and keep diamonds inside one layer, every use case box shows `execute()`, and `Logger` takes a `UseCaseLogEntry` ([#63](https://github.com/Hexablock-Suite/hexablock-app/pull/63)).
